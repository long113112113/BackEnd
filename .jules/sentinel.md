## 2024-06-08 - Fix CWE-208 Timing Leak in crypto.timingSafeEqual Wrappers
**Vulnerability:** A custom wrapper around Node.js's `crypto.timingSafeEqual` compared the length of the inputs first and returned early if they mismatched (`if (bufA.length !== bufB.length) return false;`). This re-introduces a CWE-208 timing leak by allowing an attacker to determine the exact length of the secret through timing analysis (since an early return is much faster than the full constant-time comparison).
**Learning:** Node.js's `crypto.timingSafeEqual` throws an exception if the buffers are of different lengths. Developers often try to "fix" this by adding a length check and early return, inadvertently defeating the purpose of the constant-time function and opening up a side-channel attack vector.
**Prevention:** To safely use `crypto.timingSafeEqual` with potentially variable-length inputs without introducing an early-return timing leak, hash both inputs (e.g., using SHA-256) *before* passing them to `timingSafeEqual`. Hashing guarantees both inputs will have identical, predictable lengths (e.g., 32 bytes for SHA-256) regardless of the original input length, allowing `timingSafeEqual` to execute safely and in constant time without needing a vulnerable pre-check.
