## 2025-05-27 - [CRITICAL] Prevent DoS in crypto.timingSafeEqual
**Vulnerability:** The application was double-hashing the expected and received HMACs before calling `crypto.timingSafeEqual` in `src/services/mqtt.handler.js`. While this prevented the Node.js length mismatch exception, it was an overly complex and CPU-intensive workaround. Without a proper length check, `crypto.timingSafeEqual` throws an exception when buffer lengths do not match, which can lead to an unhandled exception and crash the application (Denial of Service).
**Learning:** `crypto.timingSafeEqual` requires the two buffers to be of the exact same length. If an attacker sends a malformed HMAC string resulting in a buffer of a different length, it will crash the server if the exception is not caught or handled prior. The application previously bypassed this by unnecessarily hashing the values first.
**Prevention:** Always validate that `buf1.length === buf2.length` before passing buffers to `crypto.timingSafeEqual`. This ensures safe execution and prevents application crashes without resorting to unnecessary cryptographic operations.
